# NGROK Runbook — Local end-to-end media ingest testing

This runbook shows how to expose the local ingest server to the internet with `ngrok`, obtain a signed upload mapping, upload a file from the browser or script, and run the worker to process the uploaded raw object.

Prerequisites
- Node 18+
- `ngrok` installed and logged in (`ngrok authtoken <token>`)
- `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_URL` available locally (for local testing only)

Steps

1) Start the ingest server

```powershell
# from repository root
$env:SUPABASE_SERVICE_ROLE_KEY = '<your service role key>'
$env:SUPABASE_URL = 'https://<your-project>.supabase.co'
cd .\services\media-ingest
node server.js
```

2) Start ngrok to forward to the ingest server port (default 4001)

```powershell
ngrok http 4001

# Note the public forwarding URL printed by ngrok (e.g. https://abcd-1234.ngrok.io)
```

3) Use `client-capture.html` (or a script) but point requests at the ngrok host

- Serve the `client-capture.html` locally (or open it and change fetch targets to `https://<ngrok-host>/signed-url` and `https://<ngrok-host>/upload-proxy/:id`).

4) Upload flow

- The client will POST to `/signed-url` and receive `{ uploadUrl }`.
- The client PUTs the file to `/upload-proxy/:id` which proxies to Supabase Storage.

5) Run the worker

After a successful upload, the ingest server stores the raw object under `.tmp` (scaffold) with a job JSON. Run the worker to process it:

```powershell
cd ..\media-worker
node worker.js ..\..\.tmp\job-*.json
```

6) Verify

- Worker will upload derivatives to the segment `processed` and `thumbs` buckets. Use the Supabase Storage public URL to check or the `scripts/verify-uploads.ps1` helper.

Notes
- This runbook uses the service role key for expedience. For production, use signed URLs generated by a trusted server and avoid exposing service role keys in client or ephemeral environments.
Local end-to-end test with ngrok

1) Start ingest server (local):

```pwsh
cd services/media-ingest
npm install
node server.js
```

2) Expose server with ngrok (install ngrok separately):

```pwsh
ngrok http 4001
```

Note the public URL (e.g., `https://abcd-1234.ngrok.io`).

3) Configure client to POST to `https://abcd-1234.ngrok.io/ingest` or open `client-capture.html` served from a simple static server and change fetch target to ngrok URL.

4) Run worker to process jobs copied into `.tmp` (scaffold mode) or run with Redis:

- File-based job processing (scaffold):
```pwsh
# after posting to /ingest you get job path in response
node services/media-worker/worker.js <path-to-job.json>
```

- Redis queue mode (recommended for production tests):
```pwsh
# start a local Redis (e.g., via Docker)
docker run -p 6379:6379 -d redis:7
# set REDIS_URL and SUPABASE_SERVICE_ROLE_KEY
$env:REDIS_URL = 'redis://127.0.0.1:6379'
$env:SUPABASE_SERVICE_ROLE_KEY = '<SERVICE_ROLE_KEY>'
node services/media-worker/worker.js
```

5) Verify media: run the verification script for any affected property IDs or run the `verify-after-upload.ps1` helper.

```pwsh
pwsh ./scripts/verify-after-upload.ps1 -PropertyIds '2ab5c902-536d-4693-a255-2de307c54f3d'
```

Notes
- The worker scaffold currently uploads derivatives to `imagens-sitios-processed` and `imagens-sitios-thumbs` using the service role key. In production, use signed URLs and a queue with retries & TTL.
- Do not commit or push your service role key.
